# AI Tools_ Data Extraction & Curation Guidelines.pdf

AI Tools: Data Extraction & Curation 
Guidelines 
1. Find the Best Tools 
Do not try to collect every AI tool on the internet. 
There are millions of AI tools. Our long-term target is up to 50,000 high-quality tools, but we 
will build this in batches. 
For the first batch: 
Find and submit the best 1,000 AI tools. 
After that, we will expand in 5,000-tool batches. 
The objective is not to reach 50,000 quickly. The objective is to make every batch high quality. 
Prioritize tools that are: 
●​ Recently launched and gaining real usage 
●​ Solving a meaningful problem 
●​ Actively maintained 
●​ Currently accessible and working 
●​ Showing real user/adoption signals 
●​ Clearly differentiated or genuinely useful 
●​ Worth recommending to an AIOrbit user 
Older tools can be included only when they are still actively used, maintained and highly 
relevant. 
Do not spend time collecting large numbers of outdated or abandoned AI 
tools. 
 
2. Primary Discovery Sources 
The two primary sources for discovery are: 

1. There's An AI For That 
https://theresanaiforthat.com/tools/ 
2. Creati.ai 
https://creati.ai/ai-tools/ 
These should be reviewed systematically first. 
Additional sources 
Use the other sources provided below for discovery, cross-checking and enrichment: 
●​ ToolPilot.ai 
●​ Futurepedia 
●​ Dang.ai 
●​ OpenTools.ai 
●​ TopAI.tools 
●​ PoweredByAI.app 
●​ AI Valley 
●​ EasyWithAI 
●​ Foundr.ai 
●​ RankMyAI 
●​ AIPURE 
●​ AIToolNet 
●​ AIChief 
●​ Aixploria 
●​ The Rundown AI 
●​ Product Hunt 
●​ Official company/product websites 
●​ Startup databases 
●​ Trusted AI/technology publications 
Do not randomly search the internet and add whatever appears. 
Use: 
Discovery → Official website → Verify → Enrich → Deduplicate → Curate 
 
3. What Makes a Tool Worth Adding? 

Before adding a tool, ask: 
Would we confidently recommend this tool to an AIOrbit user today? 
If the answer is no, do not add it. 
Prioritize: 
High user value + active product + meaningful usage + good quality + current relevance. 
Strong preference 
New + high quality + useful + growing 
over 
Old + unknown + low usage + stagnant 
However, an older tool should still be included if it has strong ongoing adoption and remains one 
of the best tools in its category. 
 
4. Reject These Tools 
Do not add: 
●​ Dead/shut-down tools 
●​ Websites that no longer work 
●​ Abandoned products 
●​ Tools with no meaningful functionality 
●​ Spammy/SEO-generated tool websites 
●​ Duplicate listings 
●​ Fake/unverifiable products 
●​ Extremely low-quality tools 
●​ Outdated tools with little/no current usage 
●​ Tools that are merely minor copies of another product 
●​ Tools whose information cannot be reliably verified 
Important 
A tool appearing in a directory does not automatically mean it belongs in AIOrbit. 

Directories are for discovery. The official product website is the primary source for 
verification. 
 
5. How to Select the Best Tools 
When you find many tools doing the same thing, compare them instead of adding all of them. 
For example, if you discover 100 AI writing tools: 
Identify the strongest → compare → select the best. 
Use this simple scoring system: 
Factor 
Weight

25 
Real user value / usefulness 
20 
Current usage / adoption 
15 
Activity & maintenance 
15 
Product maturity / reliability 
10 
Recency / momentum 
5 
Differentiation 
5

5 
Total 
100 
Ranking 
90–100 → Exceptional — Strongly prioritize​
80–89 → Excellent — Include​
70–79 → Good — Include selectively​
60–69 → Average — Usually skip​
Below 60 → Reject 
Quality and current usefulness matter more than age. 

 
6. Recency & Activity Are Extremely 
Important 
For every candidate, check: 
●​ Launch date 
●​ Last update/activity 
●​ Current website availability 
●​ Whether the product is still being developed 
●​ Recent releases/features 
●​ Current pricing 
●​ Current user/adoption signals 
●​ Whether the product is still actively promoted/supported 
Priority order 
Recently launched + high quality + real usage 
↓ 
Established + actively maintained + highly used 
↓ 
Old + declining/stagnant 
The third category should generally be excluded. 
Do not build a historical database. Build a current AI tools database. 
 
7. Deduplication 
This is a major priority because the same tool will appear across many directories. 
Before adding a tool, check: 
●​ Official website/domain 
●​ Company/developer 

●​ Product name 
●​ Product URL 
●​ Same underlying product 
●​ Same company/product with different directory listings 
If the same tool appears on: 
TAAFT + Creati.ai + Futurepedia + AIPURE + Product Hunt 
create ONE AIOrbit record. 
Use the other sources for: 
●​ Discovery 
●​ Validation 
●​ Additional information 
●​ Usage/adoption signals 
Do not create duplicates because: 
●​ The tool appears on multiple directories 
●​ It has multiple categories 
●​ It has different pricing plans 
●​ It has different landing pages 
●​ It is listed under a slightly different name

Once a tool passes the quality check, collect:

9. Inputs & Outputs Must Be Specific 
Do not write vague information such as: 
Input: AI content​
Output: AI content 

Be specific. 
Example 
Inputs: Text, PDF, DOCX, URL​
Outputs: Summary, structured report, extracted data 
or: 
Inputs: Text, Image​
Outputs: Image, edited image 
Only record formats that are actually supported and verified. 
 
10. Verification Rules 
For every selected tool: 
First: 
Find it through: 
TAAFT / Creati.ai / other approved source 
Then: 
Open the official product website. 
Verify: 
●​ Product exists 
●​ Product is currently accessible 
●​ What it actually does 
●​ Pricing 
●​ Features 
●​ Current status 
●​ Company/developer 
●​ Launch/update information where available 
If reliable sources disagree: 
Prefer the official source. 

If information cannot be verified: 
Leave the field blank. Do not guess. 
We can enrich missing information later. 
 
11. Final Batch Target 
Batch 1 
1,000 best tools 
↓ 
Batch 2 
5,000 additional best tools 
↓ 
Batch 3 
5,000 additional best tools 
↓ 
Continue until we eventually reach the long-term target of approximately: 
50,000 high-quality AI tools 
But never lower the quality threshold to hit the number. 
If only 800 tools genuinely meet the standard in the first review, submit 800. 
 
Golden Rule 
We are not collecting AI tools. We are curating the AI tools worth knowing 
about. 

TAAFT + Creati.ai first → discover broadly → verify officially → check activity/usage → 
remove duplicates → score → select the best → enrich accurately. 
For Batch 1: Find the best 1,000 — not the first 1,000.

# Agents Module Extraction Guidelines.pdf

Agents Module Extraction Guidelines 
1. Objective 
We are not trying to collect every AI agent available on the internet. 
The goal is to build a high-quality, actively maintained AI Agents database. 
Prioritize agents that are: 
●​ Actually functional and available to users 
●​ Recently launched or recently updated 
●​ Actively maintained 
●​ Getting meaningful adoption/attention 
●​ Solving a real workflow or business problem 
●​ Clearly agentic — capable of executing tasks/workflows, not just being a basic chatbot 
●​ Useful enough that someone would genuinely want to discover and use them 
Quality > quantity. 
 
2. Primary source — Creati.ai 
The first and primary discovery source must be Creati.ai's AI Agents directory: 
Creati.ai — AI Agents 
Use it as the starting point for agent discovery. Creati.ai currently indexes thousands of AI 
agents and organizes them across categories such as general-purpose assistants, workflow 
automation, coding, research, sales, customer service, etc. (Creati.ai) 
The team should first extract the strongest and most relevant agents from this source, 
rather than randomly searching the web. 
 
3. Other sources for discovery 
After Creati.ai, use additional AI-focused sources for discovering and validating agents. 
Priority: 

1.​ Creati.ai — AI Agents 
2.​ Futurepedia / AI-agent-related listings 
3.​ AI-specific directories and agent marketplaces 
4.​ Product Hunt — newly launched AI agents 
5.​ GitHub — active/open-source agents 
6.​ Official company/product websites 
7.​ AI startup databases 
8.​ AI newsletters and launch lists 
9.​ TechCrunch / major AI publications for significant launches 
10.​Reddit/community discussions for discovering genuinely popular agents 
Futurepedia, for example, maintains an AI-focused directory covering business, productivity, 
workflow automation and other AI categories. (futurepedia) 
Do not use generic databases as the primary source. 
 
4. Recency is extremely important 
For every agent, check when it was launched or substantially updated. 
Priority 1 — Recently launched 
Give the highest priority to agents launched within the last few months. 
These should be actively surfaced because the Agents ecosystem changes extremely quickly. 
Priority 2 — Older but still active 
An agent launched 6–12+ months ago can absolutely be included if: 
●​ It is still active 
●​ The product is maintained 
●​ It has meaningful users/adoption 
●​ It continues receiving updates 
●​ It remains relevant 
●​ It has strong reputation/traction 
Exclude 
Do not include agents that are: 
●​ Dead 

●​ Abandoned 
●​ No longer accessible 
●​ Permanently shut down 
●​ Clearly outdated 
●​ Just an old landing page 
●​ No longer maintained 
●​ Listed only because they existed historically 
 
5. What qualifies as an "Agent"? 
Don't classify every AI tool as an agent. 
A strong agent should generally be capable of taking actions or executing a multi-step 
task/workflow, rather than simply generating a response. 
Examples of strong agent characteristics: 
●​ Can plan and execute tasks 
●​ Can use external tools 
●​ Can interact with websites/apps 
●​ Can perform multi-step workflows 
●​ Can operate autonomously or semi-autonomously 
●​ Can monitor something and take action 
●​ Can execute coding tasks 
●​ Can conduct research and produce results 
●​ Can act as a digital worker 
●​ Can operate across multiple applications 
A basic: 
"AI image generator" 
should generally remain a Tool, not an Agent. 
But: 
"AI agent that researches competitors, collects information, analyzes it and 
produces a report" 
is much more appropriate for the Agents module. 
 

6. Focus on useful agents 
We don't need thousands of low-quality agents just to increase the count. 
Prioritize: 
Business Automation → Coding → Research → Customer Support → Sales → Marketing 
→ Data Analysis → Knowledge Management → Personal Productivity → Workflow 
Automation → Autonomous Agents 
The existing category structure in the UI is a good starting point for classification. 
Creati.ai itself currently uses categories spanning workflow automation, digital workers, 
general-purpose assistants, coding assistance, research, data analysis, sales, marketing and 
other specialized areas. (Creati.ai) 
 
7. Required data for every agent 
At minimum, extract: 
●​ Agent name 
●​ Official website 
●​ Description 
●​ Category 
●​ Subcategory 
●​ Company/creator 
●​ Launch date 
●​ Last updated date, if available 
●​ Pricing 
●​ Free / Freemium / Paid 
●​ Platform 
●​ API availability 
●​ Open-source status 
●​ Supported models 
●​ Integrations 
●​ Primary use case 
●​ Country/company information where available 
●​ Official social links 
●​ GitHub repository where applicable 
And importantly: 

Active / Inactive status 
This allows us to continuously remove or deprioritize dead agents. 
 
8. Verification rule 
For every agent discovered through a directory: 
Directory → Official website → Verify 
Do not blindly copy the directory's information. 
The official website should be used to confirm: 
●​ The agent actually exists 
●​ It is currently available 
●​ What it actually does 
●​ Pricing 
●​ Product capabilities 
●​ Company/creator 
●​ Current status 
 
9. Don't inflate the database 
We should not have a target like "collect 10,000 agents no matter what." 
If we find: 
3,000 excellent agents → stop. 
That's better than: 
10,000 agents containing thousands of dead, duplicate or useless products. 
The objective is to make AIOrbit the place where someone can discover the best active AI 
agents, not the place with the largest number of scraped records. 
 

10. Deduplication 
Agents will frequently appear under multiple names/sources. 
Use: 
Official product URL + domain + company + product name 
to identify duplicates. 
For example, if the same agent appears on: 
●​ Creati.ai 
●​ Futurepedia 
●​ Product Hunt 
●​ GitHub 
●​ the company's website 
it should become one AIOrbit agent, with the different sources used for enrichment/verification. 
 
Final instruction to the team 
Start with Creati.ai's AI Agents directory as the primary discovery source. 
Extract the highest-quality, active and relevant agents first. Prioritize agents 
launched in the last few months, but also include older agents that remain 
highly active, maintained and widely used. Use other AI-specific directories, 
Product Hunt, GitHub, official websites and credible AI publications for 
additional discovery and validation. Do not try to collect every agent on the 
internet. Do not fill the database with inactive, duplicate, low-quality or barely 
useful agents just to increase the count. The goal is a high-quality, current 
and useful AI Agents database — quality and activity first, quantity second.

# Companies Module Extraction Guidelines.pdf

 
Companies Module Extraction Guidelines 
1. Primary objective 
The Companies module should contain companies where AI is a meaningful part of the 
company's product, technology, or core business. 
We are not building a generic global company database. 
Prioritize: 
●​ AI-native companies 
●​ AI model companies 
●​ Generative AI companies 
●​ Agentic AI companies 
●​ AI infrastructure companies 
●​ AI developer/tooling companies 
●​ Computer vision companies 
●​ Voice AI companies 
●​ Robotics/physical AI companies 
●​ AI cybersecurity 
●​ AI healthcare 
●​ AI fintech 
●​ AI enterprise software 
●​ AI research companies 
●​ AI hardware/chips specifically built for AI 
●​ AI platforms and AI-as-a-service companies 
A company should not be included merely because it uses AI internally. 
For example, a normal SaaS, consulting, e-commerce, manufacturing, or fintech company that 
has added an AI feature should generally not be treated as an AI company. 
This distinction is important. Tracxn, for example, defines AI-Native as companies where AI is 
the core value proposition and primary product infrastructure, rather than AI simply being added 
to an existing product. (help.tracxn.com) 
 

2. Source priority — VERY IMPORTANT 
Do not start with generic company databases and scrape everything. 
Tier 1 — AI-specific sources 
Start with sources that are already focused specifically on AI companies. 
Primary source should be: 
There’s An AI For That (TAAFT) — use its company ecosystem as one of the major discovery 
sources. 
Then use other AI-specific directories, AI startup lists, AI infrastructure lists, AI funding lists, AI 
accelerator portfolios, etc. 
The goal is: 
First build the 8,000 strongest/relevant AI companies from AI-focused 
sources. 
Only after this should we expand the dataset. 
 
Tier 2 — AI-specific sections of major databases 
Use: 
●​ Crunchbase — Artificial Intelligence companies 
●​ Crunchbase — Artificial Intelligence startups 
●​ AI-specific Crunchbase hubs and categories 
Crunchbase currently has dedicated AI company/startup datasets of roughly 10K 
organizations, making it a particularly useful secondary source for reaching the initial target. 
(Crunchbase) 
Use the AI-specific datasets, not the general Crunchbase company database. 
 
Tier 3 — Specialized startup databases 
Use sources such as: 

●​ Tracxn 
●​ AI startup databases 
●​ AI accelerator portfolios 
●​ AI VC portfolios 
●​ AI industry reports 
●​ AI infrastructure lists 
●​ AI awards/lists 
●​ AI-specific research/company rankings 
Tracxn is particularly useful because it has explicit AI categories such as Artificial Intelligence, 
AI Infrastructure, Generative AI, Agentic AI, NLP, AI-native, Computer Vision, Voice AI and 
AI-as-a-Service. (Tracxn) 
Its AI Infrastructure lists can also be used for discovery. (w.tracxn.com) 
 
3. Generic databases are NOT primary 
discovery sources 
Do not use: 
●​ Wikipedia/Wikidata 
●​ Generic company databases 
●​ Generic business directories 
●​ Random company lists 
●​ Generic web directories 
as the primary source for discovering companies. 
These can be used later for enrichment and verification. 
For example: 
AI-specific source → discover company​
Official website → verify/enrich​
Crunchbase/Tracxn → funding/valuation/investors​
Wikidata → additional metadata​
LinkedIn → employee/company information​
News → recent developments 
This keeps the source of truth AI-focused rather than allowing a generic database to 
determine what qualifies as an AI company. 

 
4. Extraction priority 
Build the database in this order: 
Phase 1 — Top AI companies 
Start with the most important companies globally: 
●​ OpenAI 
●​ Anthropic 
●​ Google DeepMind 
●​ xAI 
●​ NVIDIA 
●​ Mistral 
●​ Cohere 
●​ Perplexity 
●​ DeepSeek 
●​ Scale AI 
●​ Hugging Face 
●​ Cursor/Anysphere 
●​ Databricks 
●​ CoreWeave 
●​ etc. 
Don't focus only on valuation. Include important AI companies even if they are smaller or 
recently founded. 
 
Phase 2 — 8,000 AI companies 
Our first major target should be approximately: 
8,000 genuinely relevant AI companies. 
Use the combination of: 
TAAFT + Crunchbase AI + Tracxn AI + specialized AI sources + AI VC/accelerator lists 
to reach this number. 

Crunchbase alone has nearly 10,000 organizations in its AI category, so there is already enough 
dedicated AI-company coverage to build a strong initial dataset. (Crunchbase) 
 
Phase 3 — Expansion 
Only after the first ~8K are properly extracted, verified and deduplicated should we start 
expanding toward the larger company database. 
The priority should be: 
8K high-quality AI companies > 50K generic companies. 
 
5. Qualification rule 
Before adding a company, the extractor should answer: 
"Is AI genuinely central to this company's product/business?" 
YES → include 
If the answer is clearly yes. 
NO → don't include 
If AI is merely: 
●​ a feature 
●​ a marketing term 
●​ an internal technology 
●​ a minor product capability 
●​ something the company recently added 
●​ unrelated to its primary business 
 
6. Important distinction: AI Native vs 
AI-enabled 

Create an internal classification: 
AI Native 
AI is the company's core product/business. 
AI Enabled 
AI is important but not the company's fundamental product. 
AI Adjacent 
Company operates in an ecosystem related to AI but isn't primarily an AI company. 
For the initial 8K, prioritize AI Native and strong AI-focused companies. 
This will also make the company profile much more useful. Tracxn's current data model similarly 
distinguishes AI-Native companies from companies that merely add AI capabilities. 
(help.tracxn.com)

At minimum: 
●​ Company name 
●​ Logo 
●​ Website 
●​ Country

Your screenshots already show a good direction here: company → tools → models → 
repositories → news → videos → fundraises → investments.

8. Deduplication is critical 
The same company will appear across multiple sources. 
For example: 
Anysphere

Cursor / Anysphere 
Anysphere AI 
should not become four companies. 
Use: 
company domain + legal name + aliases

9. Source hierarchy for individual fields 
Don't assume one source is correct for everything. 
Use: 

Company website​

Official announcements​
→ funding rounds, acquisitions, launches

News​
→ recent events 
Wikidata/Wikipedia​
→ supplementary metadata only 
This is particularly important for financial fields. Don't copy a valuation from an arbitrary article 
when an authoritative company announcement or reliable financial database is available. 
 
10. Final rule for the team 
Do not optimize for the number of companies extracted. Optimize for the number of 
relevant AI companies extracted. 
The target should be: 
First 8,000 high-quality AI companies → verify → deduplicate → enrich → 
then expand. 
And do not fill the database with Microsoft, Adobe, telecom companies, banks, 
manufacturers, etc. simply because they have AI products unless they genuinely qualify 
under our AI-company criteria. 
That distinction is what will make AIOrbit's Companies module feel like an AI intelligence 
platform, rather than another generic company directory.

We are not trying to collect every MCP available on the internet. 
AIOrbit should contain a curated database of the best, most useful and currently active 
MCP Servers and MCP Clients. 
There may be 100,000+ MCP listings across different websites. Our job is to discover them

Quality > Quantity. Do not add an MCP just because you found it.

Do not randomly search Google and collect whatever appears first. 
Priority 1 — Creati.ai 
Start with these two sources: 
●​ MCP Servers: https://creati.ai/mcp/server/ 
●​ MCP Clients: https://creati.ai/mcp/client/ 
Go through these systematically and identify the best/relevant MCPs first. 
Priority 2 — Other quality MCP sources 
After Creati.ai, use: 
1.​ Official MCP Registry 
2.​ GitHub 
3.​ Glama 
4.​ Smithery 
5.​ Official company/product websites 
6.​ Docker MCP Registry 
7.​ Other established AI/MCP directories 

8.​ Product Hunt / AI launch sources 
9.​ Credible technology publications 
Important 
A directory is a discovery source, not proof that an MCP is good. 
Use: 
Discovery Source → Official Website/GitHub → Verify → Add 
Never: 
Directory → Copy → Add 
 
2. What Should Be Added? 
Add an MCP when it is: 
●​ Currently available 
●​ Actually useful 
●​ Maintained/active 
●​ Technically credible 
●​ Relevant to real users 
●​ Clearly identifiable

News Ingestion & Crawler Module 
For this module, your objective is to build an automated news ingestion pipeline that can 
collect, evaluate, deduplicate, rank, and publish the most important AI/business news on our 
platform every day. 
This module is different from the other modules because the primary challenge is source 
discovery + automated data ingestion + news quality selection. 
 
1. Identify Reliable News Sources 
First, create a list of approximately 100–500 high-quality English-language sources from 
which we can collect news. 
Sources can include: 
●​ Official company blogs/newsrooms — OpenAI, Google, Microsoft, Meta, NVIDIA, etc. 
●​ Trusted technology publications — TechCrunch, VentureBeat, The Verge, Wired, etc. 
●​ Major global newspapers/business publications — Financial Times, New York Times, 
Washington Post, Bloomberg, Reuters, etc. 
●​ Other credible AI, technology, startup, finance, and business publications. 
Do not focus only on the number of sources. Quality and credibility are more important. 
Create a structured source list containing the source name, URL, category, RSS/API availability, 
and crawling method. 
 
2. Build the News Crawler 
Build a pipeline that automatically checks these sources at least once or twice every day. 
The pipeline should: 
Source → Crawl/Fetch → Extract → Clean → Normalize → Store → Deduplicate → Rank 
→ Publish 
Where possible, use: 
●​ RSS feeds 
●​ APIs 
●​ Official feeds 
●​ Sitemap/news pages 
●​ Website crawling/scraping 
The goal is to minimize manual intervention. 
 
3. Extract Structured News Data 
For every article, extract and store information such as per our db table 
The data must be stored in the format required by our existing website/database. 
 

4. Do NOT Ingest Everything 
This is extremely important. 
We do not want thousands of articles every day. 
Our target is approximately: 
20–30 high-quality news stories per day across all sources. 
The system should discover many articles but ultimately select only the best and most relevant 
20–30 stories. 
 
5. Build Duplicate Detection 
The same news will often appear across multiple sources. 
For example: 
OpenAI launches a new product. 
TechCrunch, Reuters, Bloomberg, The Verge, and several other publications may cover the 
same event. 
The system should identify these as the same underlying news event and avoid publishing 
five separate copies. 
Build logic for: 
●​ URL duplication 
●​ Exact/similar headline detection 
●​ Semantic similarity 
●​ Entity/event matching 
●​ Multiple articles covering the same event 
Where multiple sources cover the same event, we should ideally retain the best/most 
authoritative coverage while recording other sources where useful. 
 
6. Build a News Importance / Ranking System 
The biggest part of this module is determining: 
Which 20–30 stories are actually worth publishing? 
Create a scoring/ranking system.

Source credibility 
●​ Is the source highly trusted? 
●​ Is it an official company source? 
Coverage 
●​ Are multiple credible publications reporting the same event? 
●​ How many independent sources are covering it?

●​ Is the story about OpenAI, Google, Microsoft, NVIDIA, Meta, Anthropic, etc.?

●​ Is the story being discussed widely? 
●​ Is there unusually high coverage or attention? 
Recency 
●​ How recently did the event happen? 
Relevance 
●​ How relevant is it to our AI/business audience? 
The system should combine these signals into a news importance score and rank stories 
accordingly.

For example: 
●​ 10 low-quality websites reporting a minor story ≠ important news. 
●​ 3 highly credible sources reporting a major AI announcement = potentially very

The ranking system should therefore consider source quality + coverage + impact +
